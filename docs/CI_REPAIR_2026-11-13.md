## Corrections

- Handler and intent fixtures allocate unique owners rather than deleting
  businesses 99 and 88, which may already have children from another module.
  They use the suite's real isolated database and no longer delete unrelated
  SQLite filenames.
- Runtime storage is fresh for each test process/worker, including serial runs
  and runs supplied with a common parent directory. Tokens, process leases and
  durable retry deadlines cannot carry over from a previous test run.
- PostgreSQL setup retries skip SQLite file cleanup, preserving the original
  setup failure instead of masking it with an undefined-path error.
- Parity tests use isolated SQLite client fixtures even in the PostgreSQL
  destination suite, retaining real consent/lease/retry checks and enabling
  foreign-key enforcement.
- Restore durable UID identity in sync push. An integer from another database
  cannot identify a record, even inside the same business.
- Keep failed applies inside the per-row savepoint and retain rejection evidence.
  Do not retry an unchecked mutation in an IntegrityError handler.
- Equal-version differing financial payloads remain held and audited once.
  Replace implementation-string tests with apply/replay/rejection behavior.
